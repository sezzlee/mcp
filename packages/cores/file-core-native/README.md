# Secure filesystem adapter

Node-API binaries implement root-handle-relative resolution, bounded snapshots and bounded traversal. No pathname-open JavaScript fallback is provided. Builds target glibc Linux x64/arm64, macOS x64/arm64 and Windows x64; Node 22/24.

The root is an object capability pinned at initialization. Concurrent writes are detected with before/after identity and metadata checks; this is not an atomic filesystem snapshot. Hard links and privileged mount changes are not separate filesystem security boundaries. Do not grant untrusted users privileges to mount filesystems over the configured root.

Prebuilds are generated by CI and included in the release tarball. Workspace builds require Node headers and a C++17 compiler. Windows builds also require the corresponding `node.lib` and the MSVC developer environment. Missing or unsupported binaries fail closed.

## Ayrı çıktı yeteneği

`openOutputRoot(sourceRoot, directory)` mevcut, handle ile sabitlenmiş kaynak kökünün altındaki bir çıktı dizininden ayrı bir oluşturma yeteneği türetir. `NativeRoot` üzerinde yazma metodu bulunmaz. `publish` yalnızca düz dosya adlarını kabul eder; mevcut girdiyi değiştirmez. Baytlar asenkron işe geçmeden kopyalanır, geçici dosyada tamamlanır ve var olan hedefin üzerine yazılmadan yayımlanır. Bu işlem çok dosyalı bir işin tamamının atomik olduğu anlamına gelmez.

Yeni yüzey için platform binary dosyası yeniden derlenmelidir. Eski veya eksik binary dosyasında JavaScript dosya erişimine geri dönüş yapılmaz.
