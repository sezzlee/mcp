# Phase 5 implementation status

Status, 2026-10-26: capability implementation and local acceptance are complete. The remote native matrix remains open before release. The [plan](implementation-plan.md) and [sanitized acceptance record](acceptance-record.json) separate completed evidence from that remaining gate.

## Implemented surface

The editor now has strict operations for cell formatting, dimensions, panes, visibility, print layout, merge/unmerge, formula write/fill and table creation/edit/conversion. Formula intent remains separate from scalar `WriteCell`. Table and column references use the shared reference machinery. New-workbook finishing and bulk-job finishing run before immutable publication. Dependent/independent publication and recovery continue to use the existing publisher.

The initial table appearance profile is the explicitly defined custom `SezzleeBlue` style or `none`. Conversion materializes the supported style and preserves direct overrides; unknown affected styles/dependencies refuse. New dynamic arrays, external-workbook formula binding and calculation remain excluded. Cross-workbook structured-formula copy refuses without an explicit dependency mapping.

## Contract refinements

- `job.finish` is published once at the job root. Dependent entries name `output`; independent entries also name `job`. Per-group execution identities include the resolved finishing changes.
- The per-advertised-bulk-tool budget was deliberately revised from 40,000 to 50,000 bytes after measuring 47,612 bytes with one shared finishing schema, versus 63,200 bytes with duplicated unions. Final complete tool definitions measure 48,060 bytes for preparation and 46,610 for execution. Kind-specific validation remains strict.
- Source/retained hashes, scalar types, literal text, cache absence and effective supported styles are independent acceptance facts. A file opening successfully is insufficient.
- Pure appearance preserves ordinary saved results and errors when there are no affected format-dependent formulas. Visibility changes require recalculation; a format/layout change in a workbook containing `CELL` conservatively invalidates the workbook's formula caches. Saved errors and uncached formulas remain distinct in reads.
- Expansion is checked against the stored-cell budget before allocating additional cells. Empty style/table requests and unsafe header changes refuse explicitly.
