# Phase 6 implementation plan: server-side formula calculation

Status: implemented and accepted. Local, independent, model, native and packed-install acceptance is recorded in the [implementation status](implementation-status.md) and [acceptance record](acceptance-record.json).

Baseline: `64b85b50ef488308cf329569d194d59d737a66d0`, the Phase 5 acceptance closure on `codex/excel-phase4-bulk`. Phase 6 joins the existing [Phase 4–5 pull request](https://github.com/sezzlee/mcp/pull/73). Phase 7 remains separate. Do not merge or publish as part of this work.

## Recorded decisions

- The user approved calculation results in tool responses **and** persistence in a new immutable `.xlsx` version. Formula text remains intact. Source files and retained versions remain unchanged.
- Excel installation must not be a runtime dependency. An independent spreadsheet application may validate fixtures and outputs.
- Support is explicit and bounded. Unsupported formulas never acquire guessed values. Formula errors, unsupported calculation, cycles, stale caches and resource exhaustion are distinct states.
- Existing formula authoring is not calculation. Existing successful authoring and editing contracts remain regression gates.
- The function list below is the implemented support contract. An engine name or its advertised function count is not evidence of Excel compatibility.

## Initial calculation contract

| Area                | Initial scope                                                                                                                       | Explicit boundary                                                                                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Operators           | Parentheses, unary `+`/`-`, exponentiation, multiplication/division, addition/subtraction, concatenation, comparisons and percent.  | Locale-independent OOXML formula syntax; no JavaScript `eval` or executable formula text.                                                                                                                                          |
| Aggregation         | `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `COUNTA`, `COUNTBLANK`.                                                                    | Independent tests distinguish direct arguments, ranges, text, blanks, booleans and errors.                                                                                                                                         |
| Conditional/boolean | `IF`, `IFERROR`, `AND`, `OR`, `NOT`, `SUMIF`, `COUNTIF`.                                                                            | Selected branches and criteria semantics are specified; unused branches must not produce spurious evaluation errors.                                                                                                               |
| Numeric             | `ABS`, `ROUND`, `ROUNDUP`, `ROUNDDOWN`.                                                                                             | Excel-compatible negative/tie behavior; reject non-finite results.                                                                                                                                                                 |
| Lookup              | Exact-match `VLOOKUP`, `MATCH`, `INDEX`.                                                                                            | Approximate matches, dynamic arrays and spill behavior remain unsupported unless separately proven.                                                                                                                                |
| References          | Relative/absolute/mixed A1 cells, rectangular ranges, quoted sheet names, cross-sheet references and supported static named ranges. | Resolve names with workbook/sheet scope; external workbooks, 3-D references and formula-defined names require explicit unsupported states. Existing Phase 5 structured references need a proven adapter or an explicit diagnostic. |
| Values              | Blank, text, finite number, boolean, date/time serial and Excel error.                                                              | Dates retain the workbook's 1900/1904 system; serial 60 and durations must not pass through lossy JavaScript dates. No locale-dependent coercion.                                                                                  |
| Dependencies        | Formula chains across supported references, cycles and changed-input recalculation.                                                 | Recompute a bounded requested dependency closure from the selected immutable version. Do not claim persistent incremental caching without evidence.                                                                                |
| Deferred            | Volatile time/random functions, iterative calculation, dynamic arrays, UDFs, external links, data connections and web functions.    | Report a reason and the offending cell/function; do not fetch resources or execute code.                                                                                                                                           |

Function inclusion is conditional on independent semantic cases. Unsupported syntax/function detection must precede publication and must not be confused with a legitimate blank result or Excel error.

## Engine decision gate

| Candidate                       | Current evidence                                                                                     | Decision                                                                                                                                                                                                                      |
| ------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HyperFormula 3.5.0              | Official project offers GPLv3 or a commercial license.                                               | Do not silently introduce a different licensing obligation into this MIT package. Requires a separate explicit licensing decision if selected.                                                                                |
| fast-formula-parser 1.0.19      | MIT; parser/evaluator; official documentation excludes external/3-D references and bracketed syntax. | Evaluate only behind a strict allowlist, bounded reference callbacks and independent semantic probes. Advertised support is insufficient; short-circuit behavior, dates/errors and structured references are blocking probes. |
| Formula.js 4.6.1                | MIT function library.                                                                                | Does not by itself supply the required workbook reference/dependency and persistence contracts. A possible function implementation dependency, not a complete engine decision.                                                |
| Bounded package-owned evaluator | Adds no runtime license dependency; can represent the exact support and budget contract.             | Preferred fallback if permissive candidates fail the required probes. Implement only the declared grammar/functions; fail closed on everything else.                                                                          |

Sources: [HyperFormula](https://github.com/handsontable/hyperformula), [fast-formula-parser](https://github.com/LesterLyu/fast-formula-parser), [Formula.js](https://github.com/formulajs/formulajs). Metadata checked 2026-10-27. Record the actual selected engine, version, transitive dependencies and measured limits before closing P6-01.

Selected: the package-owned `bounded-excel-v1` evaluator, with zero new runtime dependencies. The final support contract, independently checked cases, exact limits and exceptions are recorded in the implementation status. P6-00–P6-07 and F6-01–F6-07 are closed by that evidence and the successful full native/packed CI run.

## Integration seams

- `src/format/formula-authoring.ts`, `formula-edit.ts` and `structured-reference.ts`: existing authored/reference semantics. Reuse validated contracts without widening support silently.
- `src/format/preserved-workbook.ts`, `ooxml-cell.ts` and `presentation-workbook.ts`: preserved XML mutation and typed cached-value writing.
- `src/authoring/`, `src/tools/writing.ts` and existing version/publication services: typed input, write authority, exact source identity and immutable output.
- `src/grid/cell-value.ts`, `excel-serial.ts` and `src/platform/limits.ts`: existing scalar representation, serial systems and budgets.
- `packages/lab/excel-lab`: independent outputs, known answers and agent scenarios. Keep product-specific material out of this public repository.

Keep Excel vocabulary in `excel-mcp`. Shared file/MCP/OOXML cores remain format-neutral. Add no test-only production exports or broad public surface merely for testing.

## Verification sequence

1. Baseline: `pnpm turbo run test --filter=@sezzlee/excel-mcp --filter=@sezzlee/excel-lab`.
2. During implementation: focused owner specs through Turbo; use the strongest observable boundary and independent expected values. Bug regressions demonstrate the intended pre-fix failure.
3. Final: Turbo build, test, lint and check-types for changed packages and affected dependencies; repository boundaries and formatting checks for changed files.
4. Run relevant existing corpus, preservation, bulk and retained-version cases against the changed runtime. Existing test counts are historical until rerun.
5. Independently open/recalculate produced fixtures in LibreOffice or another available spreadsheet engine; validate OOXML packages when the tool is available. Compare typed values, tolerance policy, formulas and cache metadata, not just successful file opening.
6. Run Qwen calculation scenarios when its configured Ollama endpoint is reachable. Record missing endpoint/model access separately from deterministic correctness.
7. Record final revision/source identity, commands, counts, failed/skipped checks, engine/license choice and evidence in `implementation-status.md` and a sanitized acceptance record. Update PR #73 without merging it.
