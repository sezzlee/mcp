# Sezzlee MCP documentation

The Sezzlee MCP documentation site at <https://docs.sezzlee.app>. TanStack Start (Vite) + Mantine + Tailwind CSS.

```bash
pnpm --filter @sezzlee/docs dev     # http://localhost:5180
pnpm turbo run build --filter=@sezzlee/docs
```

## Content

Each product has a quickstart (`src/content/<product>/00-quickstart.md`), recipes under
`recipes/` and generated pages under `reference/`. The filename gives the order and the slug, the
first `#` line gives the title (`excel-mcp/00-quickstart.md` → `/docs/excel-mcp/quickstart`). The
sidebar and the home page are generated by `src/lib/content.ts` from `src/content/products.json`;
retired slugs redirect through `src/content/redirects.json`.

`pnpm --filter @sezzlee/docs validate` enforces the structural rules (section folders, product
registration, unique slugs, `# Title`, directives, redirects, internal link targets). `pnpm lint`
runs it too.

Site content and UI strings are written in **English** — this site is sezzlee's public face. `packages/http/spec/`
is in English too, because the site links to it as its normative source. There is no i18n layer: one
language, no drift.

The binding writing conventions — quickstart, recipes and generated reference, rationale folded
next to what it explains, RFC 2119 keywords confined to the spec — live in
[WRITING.md](WRITING.md) (not published on the site).

## Style layers

`src/styles/app.css` fixes the layer order and loads the brand fonts (Newsreader, Public Sans,
IBM Plex Mono); the palette is in `src/theme.ts`, matching sezzlee.app:

```css
@layer theme, base, components, mantine, utilities;
```

Tailwind's preflight (`base`) comes before Mantine, so it never overrides Mantine's component
styles; Tailwind's utilities (`utilities`) come after Mantine, so `<Button className="mt-4">`
works. This is also why `@mantine/core/styles.layer.css` is imported — never both it and
`styles.css` at once.

## Generated file

`src/routeTree.gen.ts` is generated by TanStack Router and committed to the repository; the
`check-types` task does not depend on `build`, so a clean checkout needs it present.
