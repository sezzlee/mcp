# sezzlee

`packages/servers/postgres-mcp` is the publishable PostgreSQL database server. It consumes only `@sezzlee/db-core` among sezzlee packages and follows the same platform/dialect/driver layers as `mssql-mcp`. Only its driver imports `pg` and `pg-cursor`; only its dialect mints SQL and identifiers. Cursor reads retain at most a bounded batch plus retained output; capped portals close before reuse. Cancellation physically closes the connection, so native cancellation failures are marked broken and quarantined by db-core. Verified TLS retains the original certificate hostname independently of a pinned dial address. CLI environment access stays explicit and declared in package Turbo configuration.

"Swagger for Agents": an MCP layer embedded into existing backends — spec + SDK per language.

## Package Boundaries

`packages/` is grouped by role, not by dependency — a folder tree cannot express a graph without lying, so the arrows live in this table and in each manifest. `cores/` holds shared machinery (nothing there is installable), `servers/` holds the publishable MCP servers (each has a `bin`), `http/` is the HTTP catalog line, `toolchain/` is config only, `lab/` is the evidence harness. Package **names** are flat and independent of the folder, so `--filter` and `workspace:^` never mention a group.

## Immutable Rules

- **Single source of truth**: Never manually define TS/C# types for spec concepts (`EndpointDescriptor`, `ToolDefinition`, `Fixture`, `Auth`, etc.). Change the schema → run `pnpm turbo run gen` → use the generated types. Never manually modify files under `packages/http/core/src/generated/` or `sdks/dotnet/src/Sezzlee.AspNetCore/Generated/`; they are committed to the repository.

- Layering rules are lint rules, and lint fails the build: every package runs `oxlint --deny-warnings`, because a warning nobody reads is not a guard. Each package's `oxlint.config.ts` extends `@sezzlee/oxlint-config`; an override replaces a rule's options instead of merging them, so a ban that must hold across layers is folded into every override that names the same rule, and `ignorePatterns`/`env` are not inherited through `extends`. A leading underscore marks a binding that exists on purpose without being read; a decorated controller parameter is what the NestJS SDK discovers a route from, so deleting one changes the catalogue.

- `packages/http/core/src/index.ts` may only re-export `export type` from the canonical files. Never re-export the embedded `EndpointDescriptor`/`ToolDefinition` copies from `generated/fixture.ts` (single-definition rule).

- In schemas, `$id` ≡ the file name. The following 2020-12 keywords must not be used: `prefixItems`, `unevaluatedProperties`, `$dynamicRef`, `dependentSchemas` (the code generator does not support them).

- If a schema change breaks fixtures, update the fixtures in the same change.

- **Comments**: No `//` line comments, no TODOs, no progress notes, no JSON comments — explanations go in the spec prose or documentation. Two exceptions, both `/** */` JSDoc/TSDoc:

  1. **Contract** on exported functions, classes, types and interfaces: purpose, `@param`, `@returns`. Factual only. A well-named item needs none.
  2. **Guard**, anywhere it is needed: a comment may state WHY when it protects an invariant, a security property, or a measured trap. It names what the guard is and what breaks without it, and may cite the decision, measurement or test that pins it. Precedents: [limits.ts](packages/servers/xml-mcp/src/host/platform/limits.ts) (`W >= 2S-1`), [doctype.ts](packages/servers/xml-mcp/src/host/chunk/doctype.ts) (the refused encoding families), [text.ts](packages/servers/xml-mcp/src/primitives/text.ts) (the Turkish dotted I), [listing.ts](packages/cores/file-core/src/listing.ts) (RegExp backtracking).

  Design narration is still forbidden: no restating the code, no explaining what a tier "is for", no history.

- **Language**: there is no `docs/` tree. A decision lives next to what it constrains: a normative rule in `packages/http/spec/`, a measurement or invariant in a guard comment, a package-level decision in that package's README, work not yet built in [ROADMAP.md](ROADMAP.md). All prose is English, package READMEs included. `packages/http/spec/` and `apps/docs/` are in English — the spec is the documentation site's normative source and has to be readable by the same audience. Everything machine-readable (JSON fields, tool names, code identifiers) is in English everywhere.

- Always build core through Turbo (`pnpm turbo run build`) — `pnpm --filter @sezzlee/core run build` skips generation and risks using stale types.

- Silent conflict resolution in tool naming is forbidden: a conflict is an error ([packages/http/spec/naming.md](packages/http/spec/naming.md)).

- `packages/cores/ooxml-core` carries **no format-specific vocabulary**. An `xl/`, `word/` or `ppt/` prefix, a SpreadsheetML/WordprocessingML/PresentationML namespace, or the noun "workbook", "sheet", "document" or "presentation" inside `packages/cores/ooxml-core/src` is a defect. Container nouns — package, part, relationship, archive — are ECMA-376 vocabulary and are allowed. Error instances and recovery advice arrive through the injected `OoxmlErrorFactory`; the core supplies only the factual detail it alone knows.

- `packages/cores/mcp-core` carries **no source-specific vocabulary**. It never names a file, a path, a table or a query; user-facing nouns arrive through the injected `Vocabulary` and whatever must stay secret is removed by the injected `ErrorContext.redact`.

- `packages/cores/file-core` carries **no format-specific vocabulary**. User-facing nouns arrive through the injected `Vocabulary`; error instances arrive through the injected `ErrorFactory`. A string literal saying "workbook", "sheet", "spreadsheet" or "excel" inside `packages/cores/file-core/src` is a defect.

- A published package may never depend on a `private: true` workspace package. `pnpm publish` silently rewrites `workspace:^` to the private package's `0.0.0`, the publish succeeds, and the failure surfaces in the consumer's `install`. The CI `pack` job guards this ([.github/scripts/check-npm-tarballs.py](.github/scripts/check-npm-tarballs.py)).

- No source-server tool response may bypass the payload budget. `json()` and `toToolError()` in `packages/cores/mcp-core` are the only sanctioned response constructors (`file-core` re-exports them and wraps `toToolError` to bind the root redactor); a hand-built `CallToolResult` in a product package is a defect.

- Visibility ≠ enforcement: search filtering is not a security mechanism; enforcement must always happen in the backend pipeline at invoke time.

## Commands

- `pnpm build` / `pnpm lint` (includes validation) / `pnpm check-types` / `pnpm validate`

- TS tests: `pnpm turbo run test --filter=@sezzlee/core` / `--filter=@sezzlee/mcp-core` / `--filter=@sezzlee/db-core` / `--filter=@sezzlee/mssql-mcp` / `--filter=@sezzlee/file-core` / `--filter=@sezzlee/excel-mcp` / `--filter=@sezzlee/xml-mcp` / `--filter=@sezzlee/pdf-mcp` / `--filter=@sezzlee/llm-mcp` / `--filter=@sezzlee/sdk-nestjs` (Vitest). Run them **through Turbo**, not `pnpm --filter <pkg> test`: that form skips `dependsOn: ["^build"]`, and `excel-mcp` resolves `@sezzlee/file-core` through `exports.default → ./dist/index.js`, so a bare filter can test against a stale `dist`.

- dotnet side: `pnpm turbo run build --filter=@sezzlee/sdk-dotnet` (the shim invokes `dotnet build`)

- DemoApi: `dotnet run` — located in `sdks/dotnet/samples/DemoApi`, listens on `http://127.0.0.1:5178`; MCP endpoint `/mcp` (requires a bearer token); demo shortcut `POST /auth/token {"user":"alice"|"bob"|"carol"}`; full OAuth 2.1 flow via the in-repo `samples/DemoAuthServer` mounted at `/oauth` (PRM at `/.well-known/oauth-protected-resource/mcp`)

- agent-client (MCP acceptance harness, drives both the dotnet and the Nest demo): `node sdks/nestjs/samples/agent-client/dist/main.js --scenario smoke|validation-retry|error-envelope`; `SEZZLEE_AUTH=oauth|token|bearer` (`bearer` reads `SEZZLEE_TOKEN`, for a real backend), `SEZZLEE_USER`, `SEZZLEE_BASE_URL`

- Nest demo: located in `sdks/nestjs/samples/demo-api`; run with `node dist/main.js` (first run `pnpm turbo run build --filter=@sezzlee/demo-nestjs`); same `/mcp` + `/auth/token` contract

- Docs site: located in `apps/docs` (TanStack Start + Mantine + Tailwind); run with `pnpm --filter @sezzlee/docs dev`, listens on `http://localhost:5180`; pages are markdown under `src/content/<product>/<mode>/*.md`. Served live from Cloudflare Workers at <https://docs.sezzlee.app>, deployed **manually** with `wrangler` — a docs change is not live until deployed ([apps/docs/CLAUDE.md](apps/docs/CLAUDE.md) § Deployment). This site is sezzlee's public face, so its content and UI strings are written in **English**, as is `packages/http/spec`, which the site links to as its normative source. `apps/docs` carries no i18n layer by design.

- Package boundary check: `pnpm boundaries` (`turbo boundaries`, experimental — not part of `pnpm lint`).
